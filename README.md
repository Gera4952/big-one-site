# The Big One Garage — отдельный сайт

Самостоятельный проект: React + Vite, Node.js 22+ для сборки. CRM не импортируется, её файлы и база не используются. Исходники можно хранить в отдельном Git-репозитории и переносить на любой хостинг целиком.

## Как устроен сайт

Сайт — отдельный проект без зависимостей от CRM: свой `package.json` и lockfile, своя сборка, свой (необязательный) сервер. Папку `big-site/` можно целиком скопировать в другой репозиторий или на другой хостинг. С CRM сайт связывает только одна строка — адрес приёма заявок `leadsUrl` в `src/data/site.json`.

Все настройки сайта — в `src/data/site.json`:

- `siteUrl` — адрес сайта со слешем в конце. Из него собираются canonical, `sitemap.xml`, `robots.txt` и разметка для поисковиков.
- `leadsUrl` — куда уходят заявки (см. ниже).
- телефон, часы работы, мессенджеры и т. п.

## Заявки

### Капча для отправки в CRM

Для сайта создайте виджет Cloudflare Turnstile с разрешёнными хостами `bigonegarage.ru` и `www.bigonegarage.ru`. Публичный ключ задаётся при сборке сайта как `VITE_SITE_TURNSTILE_KEY`. Секретный ключ хранится только в окружении API CRM как `ENVA_SITE_TURNSTILE_SECRET`. Если нужен другой кабинет, задайте `ENVA_SITE_TURNSTILE_TENANT` (по умолчанию `big-one`).

Сначала обновите API CRM и сборки всех публичных форм, которые отправляют в этот кабинет, затем включите секретный ключ в окружении API. После включения CRM отклоняет новые заявки этого кабинета без успешной капчи. Секрет нельзя добавлять в Git, переменные с префиксом `VITE_` и сборку сайта.

Чтобы проверить локально, можно задать `VITE_SITE_LEADS_URL` с адресом тестовой CRM и использовать официальные тестовые ключи Turnstile. Почтовый режим сайта продолжает работать через свой API.

**В CRM (по умолчанию).** Форма отправляет заявку прямо в раздел «Заявки» CRM: `leadsUrl` = адрес кабинета + `/api/leads/site`, например `https://big-one.envacrm.ru/api/leads/site`.

- Сервер для сайта не нужен — подходит любой статический хостинг: свой nginx, Timeweb, Beget, Netlify, GitHub Pages, S3.
- CRM по умолчанию принимает заявки с любого домена, поэтому при переезде в CRM ничего менять не нужно. Ограничить список сайтов можно переменной CRM `ENVA_SITE_LEAD_ORIGINS="https://bigonegarage.ru,https://www.bigonegarage.ru"`.
- В CRM работает защита: honeypot, проверка времени заполнения, не больше 5 заявок за 10 минут с одного IP, повторная отправка не создаёт дубль.

**На почту (по желанию).** Если поставить `"leadsUrl": null`, форма отправляет заявку на `<база сайта>/api/leads` — в Node-сервер из `server/`, который пересылает её на почту по SMTP.

- Скопируйте `.env.example` в `.env` и заполните SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASS, MAIL_FROM, LEAD_EMAIL. Получатель — thebigonegarage@bk.ru.
- Порт 465 — `SMTP_SECURE=true`; STARTTLS на 587 — `false`.
- `ALLOWED_ORIGINS` — точные адреса сайта через запятую, без пути и завершающего слеша.
- За nginx выставьте `TRUST_PROXY=true`.
- Запуск: `npm start`, порт 5191. Сервер отдаёт и сам сайт из `dist/client`.
- Секреты никогда не должны иметь префикс VITE_. Файл `.env` исключён из Git.
- Без SMTP форма честно сообщает о недоступности и предлагает позвонить. Перед запуском проверьте реальную доставку письма и папку «Спам».

## Локальный запуск

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 4175
```

Откройте http://127.0.0.1:4175/big-site/. Для почтового режима во втором терминале запустите `npm start`.

## Публикация рядом с CRM — envacrm.ru/big-site/ (как сейчас)

Корневая команда CRM `npm run build` собирает сайт с базой `/big-site/` и кладёт его в `dist/client/big-site/`. Для nginx используйте `deploy/nginx.conf`. Если сайт перенесён и больше не нужен в CRM, соберите CRM с `SKIP_BIG_SITE=1 npm run build` или удалите папку `big-site/` из репозитория CRM — сборка CRM её не требует.

## Готовые HTML-страницы (конструктор сайтов или простой хостинг)

```sh
npm ci
SITE_URL=https://bigonegarage.ru/ npm run pack:html
```

Получится папка `dist/html-pack/` и архив `dist/bigone-site-html.zip`:
- главная страница, прайс и страницы услуг, каждая — один HTML-файл со стилями и скриптом внутри;
- папка `assets/` с фото и шрифтами;
- иконки, `robots.txt`, `sitemap.xml`;
- `ИНСТРУКЦИЯ.txt`.

`SITE_URL` задаёт адрес для canonical и sitemap только на эту сборку, `site.json` не меняется. Страница сама знает, что она показывает (атрибут `data-page`), поэтому работает и по адресу `/prices`, и по адресу `/prices.html`. Если конструктор отдаёт картинки по другому адресу, нужна пересборка под него.

## Перенос на свой домен

1. В `src/data/site.json` поменяйте `siteUrl` на новый адрес, например `"https://bigonegarage.ru/"`. `leadsUrl` оставьте как есть.
2. Соберите сайт для корня домена:

   ```sh
   npm ci
   npm run build:root
   ```

   Для подпапки соберите с её путём: `SITE_BASE_PATH=/site/ npm run build`.
3. Загрузите содержимое `dist/client/` в корень сайта на хостинге. Нужны все файлы: `index.html`, `prices.html`, `uslugi/`, `assets/`, картинки, `404.html`, `robots.txt`, `sitemap.xml`.
4. Для своего nginx есть готовый пример: `deploy/own-domain.nginx.conf`. HTTPS подключается через `certbot --nginx`.
5. Проверьте сайт:
   - главная и `/prices.html` открываются;
   - тестовая заявка появилась в CRM в разделе «Заявки»;
   - у `robots.txt` и `sitemap.xml` новый адрес.
6. Добавьте новый адрес в Яндекс Вебмастер и Google Search Console. Коды подтверждения записываются в `site.json`: `yandexVerification`, `googleVerification`.

## Проверка для Яндекс Вебмастера

Для Masterhost публикуйте `dist/client/` целиком, включая скрытый `.htaccess` и файл подтверждения Яндекса. Сборка со внешними CSS и JavaScript позволяет браузеру кешировать их между страницами. При загрузке заменяйте файлы целиком. В Вебмастере добавьте `https://bigonegarage.ru/sitemap.xml`, проверьте регион «Москва» и отправьте на переобход главную, прайс и страницы услуг. В Яндекс Бизнесе используйте тот же адрес сайта без UTM.

Для старой копии на `envacrm.ru/big-site/` подготовлен `deploy/legacy-crm-redirect.nginx.conf`. Его правила предназначены только для этого раздела. На старом сервере замените существующие правила обслуживания страниц `/big-site/` правилами перенаправления и проверьте конфигурацию через `nginx -t`. Сам домен CRM продолжает обслуживать CRM.

После сборки `npm run test:seo` проверяет, что у каждого адреса из sitemap один HTML-документ, свой заголовок и canonical. Для отдельного HTML-пакета запустите также `SEO_BUILD_DIR=dist/html-pack npm run test:seo`.

`SITE_BASE_PATH` передаётся только переменной окружения команды сборки; Vite не читает её из `.env`.

Файлы `worker/` и `.openai/` — инфраструктура стартового шаблона Sites, их не трогайте: `npm run test:sites` проверяет сборку для этой площадки.

Не коммитьте `.env`, `node_modules`, `dist` и `artifacts`.

## Содержимое и материалы

- Выбранный дизайн: тёмный первый вариант с уменьшенной типографикой.
- Фото hero — сгенерированная иллюстрация; не выдавать за фотографию реальной команды. Рекомендуется заменить реальным снимком с тем же кадрированием.
- Цены и контакты взяты с bigonegarage.ru; перед запуском подтвердите актуальность и состав услуг. Не добавлялись неподтверждённые рейтинги, гарантии и часы работы.
- Отзывы: официальный iframe Яндекса для организации 152908357603, загружается по нажатию; есть постоянная ссылка на карточку на случай недоступности виджета. Его оформление/содержимое управляются Яндексом.
- В тексте обработки обращения отсутствуют неизвестные юридические реквизиты владельца; до production владелец должен заполнить политику фактическими данными оператора и сроками хранения в своей почте. Не выдумывайте реквизиты.
- Событие `bigone:lead-sent` возникает после ответа API об успешной отправке, содержит только услугу. Аналитический счётчик не подключён: его ID не предоставлен.

## Проверки

`npm test` проверяет приём заявок, SMTP-ошибки, отсутствие конфигурации, повторную отправку, ограничения, origin и перенос на корень домена. `npm run build` — production-сборка. Визуальные проверки записаны в design-qa.md. Реальные письма без SMTP не отправлялись.
